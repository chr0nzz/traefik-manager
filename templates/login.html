Welcome to Traefik Manager

A web interface for the routes, middlewares and services Traefik already serves. This setup takes about a minute: point it at your Traefik API, pick the views you want, and set a password. Everything here can be changed later in Settings.

Routes, middlewares, services
Create, edit and disable them through a form or raw YAML, written straight to your dynamic config file.
Live from the Traefik API
Router, service and middleware health read from Traefik itself, not from a cached copy.
Certificates and access logs
Expiry dates from your ACME store, and the access log read as analytics rather than a wall of text.
Yours alone
Nothing leaves the container. No account, no telemetry, no outbound calls you did not configure.
Appearance
Default theme
What Traefik Manager looks like for anyone who has not chosen for themselves. Each person can still override it from the toolbar.

Connect to Traefik

Traefik Manager reads everything through the Traefik API. This is the one step it cannot work without.

Traefik API
API URL
Where this container reaches the Traefik API. On the same Docker network that is usually http://traefik:8080 - the service name, not localhost. Requires api: {} in your static config.
API credentials optional
Only if your Traefik dashboard sits behind basic auth. Leave both blank when the API is reachable without credentials.
Routing defaults
Domains
A convenience list for the route form's host dropdown. It does not change your Traefik config, your TLS, or your routing - domains found in existing routes are picked up automatically, so this is just seeding.
Certificate resolver
Resolver names from your traefik.yml, comma-separated. The first becomes the per-route default. If you manage certificates outside ACME, enter none.

Route to Traefik Manager itself

Give this interface its own hostname through Traefik, so you can reach it over TLS instead of a published port. Writes a traefik-manager-self.yml into your config directory. Skip it if you already route to this container yourself.

Self route
Hostname
{% if detected_self_domain %}Detected from your existing configuration. Clear it to skip this step.{% else %}The hostname you want to open Traefik Manager on. Leave blank to skip this step entirely.{% endif %}
Internal service URL
How Traefik reaches this container from inside the network. Normally the compose service name and port.
Entry point
The Traefik entry point to attach the router to, as named in your static config - commonly websecure or https.

Choose your views

Each of these adds a tab to the navigation. Turn on what you use - an unused tab is just noise. All of them can be toggled later under Settings, so nothing here is a commitment.

Visualizations

Read-only views of routes Traefik discovers from other providers. Turn on the ones you actually run - these routes live in Docker labels or a KV store, so Traefik Manager shows them but cannot edit them.

System
Certificates
Plugins

GeoIP lookup

Certificates, Plugins and Logs each read a file that has to be mounted into this container. If it is not mounted yet, the view tells you the exact volume line to add. GeoIP resolves client addresses to countries in Logs and CrowdSec, downloading a free database on first use.

CrowdSec

If you run CrowdSec, Traefik Manager can read its local API and show who is probing this host, from which networks, with which scenarios, and what is already blocked. Leave the URL blank to skip.

Local API
LAPI URL
Where the CrowdSec local API listens. On the same Docker network that is usually http://crowdsec:8080.
Bouncer API key
Reads active decisions - the bans in force. Generate one with cscli bouncers add traefik-manager.
Machine login optional
Reads alerts, which is where scenarios, targeted paths and attacking networks come from. This complements the bouncer key rather than replacing it: with only the bouncer key you see bans but not the attacks behind them.

Git backup

Commit every configuration change to a git repository, so you get history, diffs and a one-click restore to any earlier commit. Local file backups happen regardless - this adds an off-box copy. Leave the URL blank to skip.

Repository
Repository URL
Any HTTPS git remote: GitHub, GitLab, Gitea, Forgejo, or self-hosted. Use a private repository - your dynamic config is in it.
Branch and username
The branch to commit to, and the account the token belongs to.
Access token
A personal access token with write access to that one repository. Stored encrypted, and never shown again after setup.
Push automatically
Commit and push on every configuration change. With this off, you push by hand from the Backups pane.

Notifications

Send a message when a route is saved or deleted, a backup runs, or a restore completes. This sets up one destination that receives every event; add more, and choose which events reach each one, in Settings.

Destination
Type
Payload format for the target service. Generic sends a plain JSON body you can shape yourself downstream.
Webhook URL
Where notifications are delivered.
App Token
Stored encrypted.
User Key
Stored encrypted.

Basic auth optional
Credentials for endpoints that require authentication.
